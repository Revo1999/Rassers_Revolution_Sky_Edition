# Building and publishing a release

The repository uses one source for the pack version, third-party dependencies
and gameplay overrides. Both downloads use the content in the same commit.

| Path | Purpose |
| --- | --- |
| `pack/version.txt` | Client and server release version and the RevoUtil HUD version |
| `pack/mods.lock.json` | Exact dependency files, download URLs and SHA-512 hashes |
| `pack/overrides/` | Shared quests, KubeJS recipes and starter-island data alongside the client configuration |
| `pack/server/` | Dedicated server setup script, installer pin and server-specific defaults |
| `build/mods/` | Eight compiled Revo mods, generated by Gradle |

## Build the matching client and server

1. Set `pack/version.txt` to the release version and commit it.
2. On GitHub, run **Actions → Build release archives** using that commit's branch
   or tag. Download the `revo-release-archives` artifact after the workflow
   succeeds. It contains a client `.mrpack` and a `-server.zip`.
3. To build from the local checkout on Windows, use these commands.

   ```powershell
   .\dev.cmd build collectMods
   powershell -ExecutionPolicy Bypass -File scripts/sync-mods.ps1
   python scripts/package_modpack.py
   python scripts/package_server.py
   ```

   The packagers write the archives next to the repository directory. The
   server packager uses the lock and built Revo jars directly, so building
   just the server archive skips the client dependency sync. The server
   setup downloads third-party jars from their pinned sources on the host.

Before publishing, import the client archive, install the server archive into
a fresh directory and join the server with the client. Check the starter
island, quest book, at least one overridden recipe and a RevoUtil note. Save
and restart to check that the same world and note remain available. The server
installer writes the Skyblock Builder setting before the world is generated.
See the [server README](../pack/server/README.md).
The [multiplayer audit](MULTIPLAYER-READINESS.md) records the tests and remaining
coverage for the eight Revo mods.

On GitHub, draft a release for the same commit with a tag such as
`v0.1.46-dev`, attach both archives and add the changelog. The workflow builds
artifacts for review and the author controls publishing.

## Publish on CurseForge

1. Create a **Minecraft Modpack** project. Use a square avatar of at least
   400 × 400 pixels, a summary and a description explaining the pack and
   crediting any approved third-party mods. [Project creation](https://support.curseforge.com/support/solutions/articles/9000197241-creating-and-submitting-a-project) · [Pack requirements](https://support.curseforge.com/support/solutions/articles/9000197908-exporting-a-modpack-for-curseforge-project-submission)
2. Create a Minecraft 1.21.1 NeoForge profile in the CurseForge app. Match each
   pinned mod and shader to a CurseForge file where available. Publish the
   Revo jars as CurseForge mod projects or obtain approval under the
   third-party rules. Review pins from Modrinth, FTB Maven and other download
   sources for matching approved files or explicitly approved overrides.
   A loader or file substitution needs a new client and server test.
   [Non-CurseForge mods policy](https://support.curseforge.com/support/solutions/articles/9000197913-minecraft-troubleshooting)
3. Copy the pack overrides into that profile, then use the CurseForge app's
   **Share Profile → Export Profile** to create the client ZIP. Let the app
   generate `manifest.json` and keep its export intact. Upload that ZIP as the
   main modpack file. [CurseForge export guide](https://support.curseforge.com/support/solutions/articles/9000197908-exporting-a-modpack-for-curseforge-project-submission)
4. Prepare the matching server ZIP from the approved dependency set and attach
   it through **Upload Additional Files** on the client file's page. The
   repository's server ZIP is a self-hosted setup archive. Check packaging
   and dependency rules before using it for CurseForge submission or a
   managed host. [CurseForge additional files policy](https://support.curseforge.com/support/solutions/articles/9000197279-moderation-policies)

The current client download is a Modrinth `.mrpack`. The CurseForge dependency
mapping and App export are publication steps.
